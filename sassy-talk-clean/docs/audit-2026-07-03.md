**Verdict:** Android cellular relay path is production-grade with strong E2E crypto. Desktop cellular relay works for basic internet PTT but lacks control-plane parity. Three cross-platform wire bugs block catch-up replay and break FCM wake / share-link flows on Android.

## 2. Wire Protocol Catalogue

### 2.1 Frame Envelope Rules

| Envelope | Format | Rule |
|----------|--------|------|
| **Legacy** | `[opcode:u8]` | `opcode < 0x10`; no payload |
| **TLV** | `[opcode:u8][payload_len:u16 LE][payload]` | `opcode >= 0x10` |
| **OP_REPLAY_FRAME (exception)** | `[0x19][peer_id_len:u16 LE][peer_id][encrypted_audio…]` | **Not standard TLV** — breaks client classifier |

### 2.2 Binary Opcodes

| Byte | Name | Envelope | Payload | Emitters | Consumers |
|------|------|----------|---------|----------|-----------|
| 0x01 | `OP_PTT_START` | Legacy | none | Android BLE | Android PttCoordinator |
| 0x02 | `OP_PTT_STOP` | Legacy | none | Android BLE | Android PttCoordinator |
| 0x03 | `OP_READY_ACK` | Legacy | none | BLE/local | Android, desktop UDP |
| 0x04 | `OP_PING` | Legacy | none | BLE/local | No-op |
| 0x05 | `OP_CHANNEL_SYNC` | Legacy | none | BLE/local | No-op |
| 0x10 | `OP_HEARTBEAT` | TLV | 23 B: epoch+seq+ts+state+rtt | All peers | Android, relay liveness; desktop cellular **skipped** |
| 0x11 | `OP_RECV_ACK` | TLV | 20 B | Android BLE TX | Android PttCoordinator |
| 0x12 | `OP_EOT_ACK` | TLV | 12 B | Android BLE | Android PttCoordinator |
| 0x13 | `OP_CAPABILITIES` | TLV | JSON ≤4096 B | Android peers | Android Capabilities.kt |
| 0x14 | `OP_PARTNER_OFFLINE` | TLV | peer_id | **Relay DO** | Android cellular; desktop **skipped** |
| 0x15 | `OP_PTT_START_V2` | TLV | 12 B: epoch+start_seq | Android BLE+cellular | Android; relay → FCM wake |
| 0x16 | `OP_PTT_STOP_V2` | TLV | ≥8 B: epoch(+end_seq) | Android BLE+cellular | Android |
| 0x17 | `OP_WAKE` | TLV | 16 B: epoch+sender_ts | Android | Android handleWake; relay → FCM |
| 0x18 | *(unallocated)* | — | — | — | — |
| 0x19 | `OP_REPLAY_FRAME` | **Non-TLV** | peer_id + audio | **Relay DO only** | **No client handler** |
| 0x1A–0x1C | Emergency opcodes | TLV (planned) | EmergencySignal | Not wired | Not wired |

**Encrypted audio (not an opcode):** `nonce(12) || ciphertext || tag(16)` — blind relay fan-out.

### 2.3 Cross-Platform Mismatches

| Issue | Severity | Detail |
|-------|----------|--------|
| OP_REPLAY_FRAME framing | **Critical** | Relay emits non-TLV; clients require `len == 3 + u16(1..2)`. Catch-up cannot work. |
| Android `/presence` auth | **Critical** | `PresenceClient.kt` POST/DELETE without Bearer token. Worker requires auth → 401. |
| Android `/share` API drift | **Critical** | `SessionShareLink.kt` uses wrong endpoints vs `share.js`. |
| Desktop cellular control | **High** | Skips all control frames; no liveness, wake, or partner-offline handling. |
| Desktop UDP crypto nonce | **High** | 4-byte prefix + 8-byte BE counter vs core's 8+4 LE. Incompatible with Android. |
| Desktop UDP wire format | **High** | Split `nonce‖tag‖ciphertext` vs core's `nonce‖ciphertext+tag`. |
| Stale `/workspace/cloudflare-worker/` | **Medium** | PARTNER_OFFLINE keys on session.id not stable peer param. |

## 5. Race / Lock / Lifetime Hazards

### 5.1 Android native lock topology

**StateMachine mutexes:** `state`, `transport`, `audio`, `audio_cache`, `user_registry`, `tx_handle`, `rx_handle`.

**Documented acquisition patterns:**

| Context | Order | Deadlock risk |
|---------|-------|---------------|
| TX thread | `audio` alone OR `transport` alone | None |
| RX thread | `transport` → `audio_cache` → `user_registry` → `audio` (sequential) | None |
| JNI (typical) | `JNI_STATE` → one SM lock | Contention only |
| JNI BT encode | `JNI_STATE` → `audio` → `transport` | Long critical section |
| Replay | Snapshot cache, drop JNI_STATE, then `playback_lock` → `audio` | Safe by design |

**Verdict:** No classic ABC deadlock triangle (`audio_cache ↔ transport ↔ audio`). Contention on `JNI_STATE` during BT encode is the main latency risk.

**Poison policy:** Inconsistent — JNI recovers via `unwrap_or_else(into_inner)`; audio threads panic on poison.

### 5.2 Tauri desktop hazards

| Hazard | Risk | Location |
|--------|------|----------|
| `std::sync::Mutex` in async cellular path | Medium | `cellular.rs` crypto lock in tokio tasks |
| Dual transport lifecycle (UDP + cellular concurrent) | Medium | `lib.rs` — ambiguous ConnectionStatus |
| Unbounded mpsc audio channels | Low–Med | No backpressure on decode stall |
| PTT thread abort without join | Low | `stop_tx_thread` |
| Frontend listens for events never emitted | Medium | `audio_level`, `receiving` — dead listeners |

### 5.3 Android Kotlin concurrency

- 6× `MutableStateFlow` in PttCoordinator; `ConcurrentHashMap` for peers
- `TranscriptionBridge.onAudioReceived` called from native RX thread — uses synchronized blocks before StateFlow mutation
- **Service lifecycle:** `MainActivity.onDestroy` stops service → rotation may glitch audio/BT

## 6. Security Surface Inventory

### 6.1 JNI entry points (~80 exports)

| Category | Validation | Notes |
|----------|------------|-------|
| Session/crypto | Strong | PSK len, QR expiry, sealed context |
| Wire/audio | Strong | Frame length bounds, MAX_PACKET_SIZE |
| Channel | **Weak** | `nativeSetChannel` — no 1–8 bounds |
| Strings | **Weak** | No length caps at JNI (truncated on TX wire frame) |

**Positive:** Mandatory E2E encryption on all transports; sealed URL percent-encoding; replay window (8192 nonces).

### 6.2 Worker routes & auth gating

| Route | AUTH_SECRET required |
|-------|---------------------|
| `/health`, `/` | No |
| `/auth` | Issues tokens (requires secret server-side) |
| `/ws` | **Yes** — fail-closed 503 if unset |
| `/presence` POST/DELETE | **Yes** — Android client **does not send token** |
| `/share` POST/DELETE | **Yes** — Android client **does not send token** |
| `/share/<id>` GET | No (128-bit id is capability) |
| `/dl/apk` | No |

**Token format:** `<expSec>.<hexSig>` where sig = HMAC-SHA256(`${roomId}.${expSec}`, AUTH_SECRET).

### 6.3 Stored secrets

| Secret | Location | Risk |
|--------|----------|------|
| Session PSK (32 B) | Android Keystore → EncryptedSharedPreferences | ✓ Critical path protected |
| FCM token | EncryptedSharedPreferences (`sassy_wake_state_enc`) | ✓ |
| `AUTH_SECRET` | Wrangler secret | ✓ Not in repo |
| `FCM_SERVICE_ACCOUNT_JSON` | Wrangler secret | ✓ Not in repo |
| `SEALED_CTX` static | Process memory in cellular_transport.rs | ⚠ Not zeroized on clear |
| Install UUID | Plaintext prefs | Low (opaque ID) |

### 6.4 Crypto assessment

| Path | Algorithm | Interop |
|------|-----------|---------|
| Android cellular | Core `CryptoSession` AES-256-GCM + X25519/HKDF | ✓ Android ↔ relay ↔ desktop cellular |
| Android BT/WiFi | Core `CryptoSession` via TransportManager | ✓ |
| Desktop cellular | Core `CryptoSession` | ✓ Android interop |
| Desktop UDP | Local `CryptoEngine` — different nonce layout + wire format | ✗ Not Android-interoperable |

**Deferred:** AES-GCM nonce prefix widening (4→8 bytes) — wire break, see `docs/deferred-hardening.md`.
